# 实现者子智能体提示模板

派发实现者子智能体时使用此模板。

```
Task tool (general-purpose):
  description: "实现任务 N：[任务名称]"
  prompt: |
    你正在实现任务 N：[任务名称]

    ## 任务描述

    [计划中任务的完整文本——粘贴在此处，不要让子智能体读取文件]

    ## 上下文

    [场景设置：此任务在哪里适配、依赖关系、架构上下文]

    ## 开始之前

    如果你对以下内容有疑问：
    - 需求或验收标准
    - 方法或实现策略
    - 依赖关系或假设
    - 任务描述中不清楚的任何内容

    **现在提问。** 在开始工作之前提出任何疑虑。

    ## 你的职责

    一旦你明确了需求：
    1. 严格实现任务所规定的内容
    2. 编写测试（如果任务要求，遵循 TDD）
    3. 验证实现是否有效
    4. 提交你的工作
    5. 自我审查（见下文）
    6. 汇报结果

    工作目录：[directory]

    **工作过程中：** 如果遇到意外情况或不清楚的内容，**提出问题**。
    随时暂停澄清都是可以的。不要猜测或做假设。

    ## 汇报之前：自我审查

    用全新的眼光审查你的工作。问自己：

    **完整性：**
    - 我是否完整实现了规格中的所有内容？
    - 我是否遗漏了任何需求？
    - 是否有我未处理的边界情况？

    **质量：**
    - 这是我最好的工作吗？
    - 名称是否清晰准确（与事物的功能匹配，而非工作方式）？
    - 代码是否整洁且可维护？

    **规范：**
    - 我是否避免了过度构建（YAGNI 原则）？
    - 我是否只构建了被要求的内容？
    - 我是否遵循了代码库中现有的模式？

    **测试：**
    - 测试是否真正验证了行为（而不仅仅是模拟行为）？
    - 如果需要，我是否遵循了 TDD？
    - 测试是否全面？

    如果在自我审查期间发现问题，在汇报之前立即修复。

    ## 汇报格式

    完成后，汇报：
    - 你实现了什么
    - 你测试了什么以及测试结果
    - 修改的文件
    - 自我审查发现（如有）
    - 任何问题或顾虑
```
